## A. ประเด็นที่ต้องแก้ใน FRD

### 1. ตัวอย่าง JV ใน §6.4 ไม่ balance และเครื่องหมาย FX กลับด้าน (OI-1) — **สำคัญสูง**

**อ้างอิง:** §6.3, §6.4, TC-AR-09

**ปัญหา:** FRD ระบุ Total Base Dr = Cr = 4,098.10 แต่ผลบวกด้านเครดิตจริงไม่ใช่

| ฝั่ง | รายการ | THB |
|------|--------|----:|
| Dr | AR 3,370.50 + Advance Deposit 727.60 | **4,098.10** |
| Cr | Revenue 3,150.00 + VAT 220.50 + AR 749.00 + FX Gain 21.40 | **4,140.90** |
| | ผลต่าง | 42.80 (= 2 × 21.40) |

ผลต่างเท่ากับ 2 เท่าของ FX พอดี แปลว่า FX ต้องอยู่ฝั่ง **Dr (ขาดทุน)** ไม่ใช่ Cr (กำไร):
ล้างมัดจำด้วยค่าเดิม 727.60 แต่ตัดลูกหนี้ 749.00 → ขาดอยู่ 21.40 ที่ต้องเดบิต

สูตร §6.3 (`Current − Original > 0 ⇒ Gain`) จึงใช้ไม่ได้กับโครงสร้าง JV นี้ และ TC-AR-09 ที่ขึ้น **PASS** ไม่น่าจะผ่านจริง

**ข้อเสนอ:** JV ที่ balance (ถ้ายังใช้โมเดลของ FRD):

| Account | Dr | Cr |
|---------|---:|---:|
| 1130000 AR | 3,370.50 | |
| 4110000 Room Revenue | | 3,150.00 |
| 2151000 Output VAT Pending | | 220.50 |
| 2130000 Advance Guest Deposit | 727.60 | |
| 1130000 AR | | 749.00 |
| Realized FX **Loss** | 21.40 | |
| **รวม** | **4,119.50** | **4,119.50** |

สูตร: `FX = Applied FC × (Deposit rate − Invoice rate)` ถ้า < 0 → Dr Loss, > 0 → Cr Gain

**คำถามถึง BA:** ยืนยันสูตรและแก้ตัวอย่าง §6.4 + expected result ของ TC-AR-09

### 2. มัดจำกับ TFRIC 22 และ VAT ของมัดจำ (OI-2) — **สำคัญสูง ต้องให้ที่ปรึกษาบัญชียืนยัน**

**อ้างอิง:** §2 (Tab 5 ของ ARDP), §6.2–6.4

**2.1 FX:** ตาม TFRIC 22 (Foreign Currency Transactions and Advance Consideration) เงินมัดจำรับล่วงหน้าเป็นหนี้สินที่ไม่เป็นตัวเงิน (non-monetary) รายได้ส่วนที่ลูกค้าจ่ายล่วงหน้าแล้วต้องรับรู้ด้วย **อัตรา ณ วันรับมัดจำ** — ตอนตัดมัดจำจึง **ไม่เกิด FX gain/loss**
FRD รับรู้รายได้เต็มจำนวนด้วยอัตราวันออก Invoice แล้วบันทึกผลต่างเป็น FX แทน ซึ่งทำให้ยอดรายได้ในงบต่างจากที่มาตรฐานกำหนด

**2.2 VAT:** ARDP ออกใบกำกับภาษี `TXDP` (FRD §1.2, §2 "ภาษีมัดจำ") แปลว่า VAT ถึงกำหนดตอนรับมัดจำแล้ว แต่
- JV ของ ARDP ใน §2 มีแค่ `Dr เงินสด / Cr เจ้าหนี้มัดจำ` ไม่มีบรรทัด VAT
- ตัวอย่าง §6.4 เครดิต VAT เต็ม 6.30 USD อีกครั้งตอน Invoice และเดบิตมัดจำเต็ม 21.40 USD (รวม VAT)

ถ้า VAT ของมัดจำถูกบันทึกไปแล้วตอน ARDP ส่วนที่ 1.40 USD จะถูกนับซ้ำ

**ตัวอย่างทางเลือกตาม TFRIC 22** (สมมติมัดจำ 21.40 = 20.00 net + 1.40 VAT และ ARDP บันทึก `Dr Cash 727.60 / Cr Deposit 680.00 / Cr Output VAT 47.60` ไปแล้ว):

| Account | Dr | Cr |
|---------|---:|---:|
| Advance Deposit (20.00 × 34) | 680.00 | |
| AR (74.90 × 35) | 2,621.50 | |
| Revenue (20.00 × 34 + 70.00 × 35) | | 3,130.00 |
| Output VAT (4.90 × 35) | | 171.50 |
| **รวม** | **3,301.50** | **3,301.50** |

**คำถามถึง BA:**
1. ใช้โมเดลไหน — FRD เดิม (FX ตอนตัดมัดจำ) หรือ TFRIC 22
2. ARDP บันทึก VAT อย่างไร (มีบรรทัด Output VAT ตอนรับมัดจำหรือไม่)
3. ตอน Invoice ต้องหัก VAT ส่วนที่ออก TXDP ไปแล้วหรือไม่

### 3. จังหวะ post GL ขัดกับ LOA (OI-3) — **สำคัญสูง**

**อ้างอิง:** §3.1 (STATUS), §3.2 (Approve), §4 (Submit), §7 (flowchart)

| จุดใน FRD | บอกว่า |
|-----------|--------|
| §7 flowchart | `ProcessSubmit → SendToGL → LOAFlow` — post GL **ตอน Submit ก่อนอนุมัติ** |
| §3.1 status | `Draft → Submitted → Approved → Posted` — Posted อยู่ **หลัง** Approved |
| §3.2 ปุ่ม Approve | "อนุมัติและส่งต่อขั้นถัดไป **หรือโพสต์ลง GL**" — post ตอนอนุมัติขั้นสุดท้าย |
| §3.2 ปุ่ม Reject | เปลี่ยนเป็น Void — ถ้า post ไปแล้วตอน Submit ต้องกลับรายการ GL ด้วย แต่ FRD ไม่ได้พูดถึง |

PRD v1.0 เดิมกำหนด "manual review before GL posting"

**ข้อเสนอ:** post GL เมื่อ **Financial Controller อนุมัติขั้นสุดท้าย** (สถานะ `Approved → Posted`) ส่วน Reject/Send Back จะไม่ต้องกลับรายการ GL — สอดคล้องกับ status และ PRD เดิม

**คำถามถึง BA:** เลือกจังหวะ post และแก้ flowchart §7 ให้ตรงกัน

### 4. ใบเสร็จ (ARRC) อยู่ในตาราง Invoice header (OI-4)

**อ้างอิง:** §5.1 `doc_prefix` ENUM รวม `ARRC`

ใบเสร็จมีโครงสร้างต่างจาก invoice — ต้องมีประเภทการชำระ บัญชีธนาคาร/เช็ค WHT ที่ถูกหัก ยอดรับสุทธิ และการจัดสรร (allocation) ไปยังหลาย invoice ซึ่งไม่มีคอลัมน์ใดใน `ar_invoice_header` รองรับ
ฝั่ง AP ที่ implement แล้วแยก `ap_invoice` กับ `ap_payment` และ PRD v1.0 ก็มี `ar_receipt_header` + `ar_receipt_allocation`

**ข้อเสนอ:** เอา `ARRC` ออกจาก `ar_invoice_header` และทำ FRD ของ Receipt แยก (แบบเดียวกับ AP Payment FRD v2.16)

**คำถามถึง BA:** มีแผนทำ AR Receipt FRD หรือไม่ และเมื่อไร

### 6. WHT: header ว่าไม่ลง GL แต่ Tax 2 มีบัญชี WHT (OI-6)

**อ้างอิง:** §3.1 (Wht Amt.), §3.4 ส่วนที่ 3 (Tax 2), §3.9 footer คอลัมน์ "TAX 2 (WHT / OTHER)", TC-AR-10

- Header `wht_amount` — **ไม่มีผลต่อ GL** ตอนตั้งหนี้ รับรู้ตอน Receipt
- Tax 2 ระดับบรรทัด — "ภาษีขายเสริม **หรือภาษีหัก ณ ที่จ่าย**" มีบัญชี `2180000` และถูกรวมใน Total (= Net + Tax 1 + Tax 2) ซึ่งจะลง GL ตอนตั้งหนี้

ถ้าตั้ง Tax 2 เป็น WHT จะ (ก) ลง GL ขัดกับกฎ header และ (ข) บวก WHT เข้ายอดลูกหนี้ ทั้งที่ WHT ควร **ลด** ยอดรับ

**ข้อเสนอ:** Tax 2 ใช้กับภาษีขายเสริมเท่านั้น (เช่น service charge / ภาษีท้องถิ่น) ส่วน WHT ใช้ header field อย่างเดียว และแก้ป้าย footer เป็น "TAX 2 (OTHER)"

**คำถามถึง BA:** Tax 2 มีกรณีใช้งานจริงอะไรบ้าง

## B. Dependency ฝั่ง backend (ไม่ต้องแก้ FRD)

### 7. ยังไม่มีสิ่งที่ AR ต้องใช้ใน backend (OI-7)

ตรวจกับ `carmen-turborepo-backend-v2` (tenant schema, micro-business) ณ 2026-09-28:

| สิ่งที่ FRD อ้างถึง | สถานะใน backend | ผลกระทบ |
|---------------------|-----------------|---------|
| `ar_profile` (customer master: currency, credit term, tax entity) | **ไม่มี** — มีแค่ `tb_vendor` | ต้องทำก่อน AR ทุกเอกสาร — FRD ยังไม่ได้ spec ตารางนี้ **(ขอ FRD Customer Master)** |
| PMS Night Audit Interface JV + unbilled folio พร้อมยอดคงเหลือ | **ไม่มี** | ฟีเจอร์ Add Folio และกฎ "ไม่ post GL ซ้ำ" ทำได้ก็ต่อเมื่อมี interface นี้ |
| GL period close | มี `tb_gl_period` | ใช้กับ ERR_AR_001 ได้ |
| Tax profile | มี `tb_tax_profile` | ใช้กับ Tax 1/2 ได้ (ต้องเช็คว่ารองรับ `VAT07_INC`/`VAT07_ADD`) |
| Dimensions | มี `tb_gl_dimension*` (จากงาน AP) | ใช้ได้ |
| Default AR account / dept | — | ไม่ควร hardcode `1130000`/`GEN`/`USD` ตาม §5 — ใช้ `gl_setting` และ base currency ของ BU แบบ AP |

**คำขอ:** FRD ของ Customer Master และ spec ของ PMS interface (อย่างน้อยรูปแบบข้อมูล folio ที่ AR จะดึง)
